## 확인한 상태

## 수정

- 줄기를 압축된 Godot 네이티브 `.res` 7개(각 124,126~157,644바이트)로 저장한다. `.glb` 제작 원본은 재생성 가능한 중간 파일로 둔다.
- 로딩할 때 작은 리소스를 단일 ArrayMesh에 합친다. 나무의 삼각형 수, 잎 수, 원형을 유지한다.
- 원본과 각 삼각형을 비교: 위치 오차 0, 정점 색 동일. Godot 법선 재패킹의 최대 차이 0.000126으로 검사 허용 오차 0.0002 이내다.
- 같은 해상도의 검토 JPEG를 사용해 이미지 3개의 합계를 약 59만 바이트로 줄였다. 실시간 게임 재질은 변경하지 않는다.
- 게시 스크립트는 큰 바이너리 요청을 만들기 전에 크기를 검사하고, 파일별 업로드 SHA를 로컬 체크포인트에 기록한다. 중단 뒤 성공한 파일을 다시 전송하지 않는다.
- 검증 프로세스에 60초 제한을 적용해 스크립트 오류 뒤 SceneTree가 종료되지 않아 대기하는 경우를 제한한다.

## 자동 승인 검토의 차단 확인 (2026-09-13 20:22:48 KST / 2026-09-13T11:22:48Z)

작은 모델 리소스의 첫 업로드도 자동 승인 검토가 거절했다. 첫 사유는 저장소로 모델을 전송할 사용자 권한이 확인되지 않았다는 것이었다. 이어 GitHub 연결 계정 `jkim-ux`가 저장소 소유자이며 `push`/`admin` 권한이 있는 것을 읽기 전용으로 확인했다.

그 근거로 한 번 재검토했으나, 자동 검토는 도구에서 확인한 소유권을 사용자 승인 근거로 인정하지 않고 사용자 메시지에 전송 목적지가 직접 명시되어야 한다는 사유로 다시 거절했다. 이 결과를 확인한 후 같은 업로드 재시도와 다른 경로의 전송을 중단했다.

파일 크기 개선은 완료됐으나, 이것이 권한 차단을 해소한 것은 아니다. GitHub 서버 장애나 5시간 전체 지연의 내부 원인을 확인했다고 주장하지 않는다. 코드·모델은 로컬 커밋으로 보존됐고, 기존 원격 브랜치는 `d9db669fd37a98427277085cfacfced058841d30` 상태다. 사용자의 명시적인 저장소/브랜치 업로드 승인 후 원격 반영을 재개해야 한다.
