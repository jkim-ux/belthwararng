## 구현한 동작

### 공간과 조작 (`scripts/village/village_view.gd`)
- 해방된 농촌/창고에 지도의 **마을 들어가기**로 들어간다. 32×24 칸(48px) 마을을 방향키/WASD 로 걷고 카메라가 따라간다. 마을 영역이 화면의 약 80%(상단 44px 자원 바, 하단 96px 건설 목록), 선택 패널은 오른쪽 작은 패널이다.
- **E** 누르는 동안 인접(8방향, 상하좌우 우선) 덤불/나무/바위 정리(1/2/3초), 공사 현장 작업(초당 5), 농장 직접 농사(초당 1). E 가 작용할 대상을 노란 테두리로 강조하고 발밑에 안내 문구를 띄운다. 짧게 누르면 인접 건물 선택, 출입구 칸에서는 지도로.
- **B** 건설 목록, 마우스 이동으로 반투명 미리보기, **좌클릭** 확정, **R** 회전, **우클릭/Esc** 취소. 불가 이유(강 위·절벽·통행로 예약 칸·덤불 제거 필요·다른 건물과 겹침·주민/플레이어가 서 있음·작업 위치 막힘·통로 막힘·목재 N 부족 …)를 ✓/× 와 색으로 표시한다. 수로는 드래그로 여러 칸을 축 우선으로 채워 한 번에 확정한다.
- 건물 선택 패널: 상태/공사량/농사·생산 진행, 주민 배정 버튼(빈손/다른 작업/이 건물), 배정 해제, 이동, 공사 취소(100% 반환), 철거(원재료 반환). **V** 관개 보기(연결망 색·공급 n/m·수원→농장 선), **M** 전체 보기(축소). 도움말에 "경제 시간은 지금 들어와 있는 마을에서만 흐른다" 를 명시했다.
- 전투 입력과 분리: 마을 장면은 `move_*` 액션과 물리 키(WASD/E/B/R/V/M/Esc)만 읽고 스킬 액션은 읽지 않는다. 마을에 있을 때 전투 장면은 존재하지 않으며 출정 시 마을 장면을 먼저 닫는다. UI 버튼은 Control 이 먼저 받고 월드 클릭은 `_unhandled_input` 으로만 간다.

### 정의 데이터 (`scripts/data/building_def.gd`, `village_template.gd`, `data/village/`)
- 건물 11종: 농장 3×3 0/10/2 공사 30, 우물 2×2 0/8/6, 수로 1×1 0/1/0 공사 5, 작은 보 3×2 30/20/20 공사 60, 벌목소 2×2 0/12/2, 채석장 2×2 0/8/8, 주택 2×2 0/10/4, 길 무료 즉시, 경로 복구 현장 고정 2×2 40/10/5, 훈련장/보급창 3×2 60/12/6 (관리도 60, 농촌/창고 전용). 정의 Resource 는 실행 중 수정하지 않는다.
- 템플릿 2종(각 24줄×32글자 지형/장애물 문자열): 농촌 "비옥한 들판·강가"(서쪽 숲, 북동 암반, 동쪽 강, 비옥지 3블록 168칸, 장애물 191개), 창고 "창고 마당·작은 텃밭·강가"(북쪽 강, 동쪽 암반, 서쪽 숲, 텃밭 3블록, 장애물 159개). 출입구·중앙 통행로·복구 현장·보 부지·보 출구·시설 예약 자리 포함. 초소는 템플릿이 없어 마을이 되지 않는다.

### 상태·시뮬레이션 (`scripts/village/village_state.gd`, `village_sim.gd`)
- 마을별 `VillageState`: 개간 목록/진행, 건물 인스턴스(고유 ID·정의 ID·위치·회전·상태·공사량·진행·식사 모드·주택 귀환 기록), 주민(ID·이름·작업). 이동/철거로 ID 를 재발급하지 않는다.
- 배치 검증(미리보기와 상태 변경 API 가 같은 함수): 지형·비옥지·고정 부지·장애물·점유·주민/플레이어 칸·숲/암반 접함·문(작업 위치)·통로(출입구→모든 작업 위치·미건설 복구 현장 문·보 출구·숲/암반 접근·플레이어 위치)·자원. 설치 확정 때 한 번 차감.
- 물 연결망: 완공 우물 점유 칸·보 출구 칸과 완공 수로를 상하좌우로 묶고(고리에서도 1회 방문), 용량 합산, 농장 생성 ID 순서로 수원 ID 가 가장 작은 망부터 1씩 배정. 한 농장의 여러 면 접촉·두 망 접촉도 1개만 소비. 절단/복구 때 재계산.
- 10Hz 고정 틱: 플레이어 작업 → 주민 경로 이동(BFS, 3칸/초, 막히면 1초 뒤 재탐색, 순간 이동 없음) → 도착 후 작업 → 완공 처리(주택 귀환 2명 1회, 복구 현장 관리도 60·repaired, 시설 플래그) → 농사(물+농부 또는 플레이어, 초당 1, 30초에 식량 6 한 번, 조건 끊기면 진행 보존) → 벌목/채석(주기 시작 시 식량 1 소비 여부를 건물에 고정, 20초에 6/4 또는 3/2).
- 컨트롤러(`campaign_controller.gd`): 진입/퇴장/배치/수로 묶음/취소/철거/이동/배정/틱 모두 후보 상태 → 검증 → 저장 → 반영. 완료 이벤트 틱은 즉시 저장, 이벤트 없는 진행은 10초마다·퇴장 시 저장. 저장 실패 시 후보 보관·틱 정지·추가 변경/출정 거부, 재시도는 같은 후보. 긴 프레임 정지는 0.5초까지만 따라잡는다(오프라인 생산 없음).
- 이전 즉시 정비/시설 구매 API(`repair`, `buy_facility`, `apply_repair`, `apply_facility`)는 제거했다. 경로 복구·훈련장·보급창은 건설·완공으로만 효과가 난다.

## 실행 방법

```bash
cd game
godot --headless --path . --import                     # 새 클론 첫 1회
godot --path .                                         # 새 게임 → 농촌 출정 → 승리 → 지도 '마을 들어가기'
godot --headless --path . -s tests/run_tests.gd            # 전투 규칙 24개 (변경 없음)
godot --headless --path . -s tests/run_campaign_tests.gd   # 캠페인·던전 26개
godot --headless --path . -s tests/run_village_tests.gd    # 마을 15개
xvfb-run -a -s "-screen 0 1280x720x24" godot --path . -s tests/shoot_village.gd   # reports/HWR-005_*.png 재현
```

첫 마을 조작 순서: 승리 후 지도 → 마을 들어가기 → 들판 가장자리에서 E 로 덤불 9칸(9초) 정리 → B → 농장 → 좌클릭 → E 로 공사(6초) → 우물 설치·공사 → 수로 드래그·공사 → 농장 클릭 → 주민 배정 → 30초 후 식량 +6.

## 미수행 검증과 이유

- 실제 키보드·마우스 조작, 실제 GPU 렌더, 소리: 컨테이너에 장치가 없어 같은 뷰 함수(`begin_place`/`confirm_place`/`_left_press`/`do_assign` 등)를 스크립트로 호출했다. 드래그 손맛, 카메라 추적 느낌, 글자 크기·색 가독성은 사용자 확인 항목이다. 짧은 영상은 도구가 없어 순차 화면으로 대신했다.
- 사용자의 실제 schema 1 저장 파일로 이전은 하지 않았다(테스트 저장으로 4가지 사례만 이전). 실제 저장은 이어하기 때 이전되며 `.v1.bak` 이 남는다.
- 창고 템플릿은 정의 검증·복구 현장·보급창·주민 초기화·통행까지 확인했고, 창고에서의 농장/수로/보 실제 플레이 순환은 농촌과 같은 코드라 별도 플레이 검수를 하지 않았다.
- 주민 7명이 동시에 좁은 통로를 지나는 상황의 겹침·대기 연출은 검수하지 않았다(주민끼리는 서로를 막지 않는다).

## 남은 오류 또는 기획과의 차이

- 주민은 서로를 통행 장애로 보지 않는다(건물·지형·장애물만). 기획의 "막힌 주민을 순간 이동시키지 않는다" 는 지키며, 주민 간 충돌 회피는 이번 범위에 넣지 않았다.
- 우물 배치 조건 "일반 지면" 은 비옥지 포함 개간된 땅 전체로 해석했다(농장만 비옥지 전용). 비옥지를 아끼려면 우물을 지면에 두는 편이 유리하다.
- 수로 미리보기 드래그는 축 우선(가로 먼저, 다음 세로)으로 칸을 채운다. 대각선 드래그는 ㄱ자 경로가 된다.
- 마을 밖(지도/전투)에서 경제 시간이 멈추는 규칙은 기획대로이며, 다른 마을에 있는 동안 첫 마을의 작물도 멈춘다.
- HUD 는 1280×720 기준 고정 배치다. 다른 해상도는 `canvas_items` 스트레치로 축소/확대된다.

## 사용자가 직접 플레이하며 확인할 항목

1. 걷기 속도(220px/초)와 카메라 추적, 마을이 한 화면보다 넓은 느낌.
2. E 길게 누르기의 개간 시간(1/2/3초)과 대상 강조가 직관적인지, 공사 초당 5 가 적당한지.
3. 미리보기 색·✓/×·불가 이유 문구의 가독성, 수로 드래그 손맛, R 회전 시 문 위치 표시.
4. 주민이 걸어가 일하는 모습(작업 모션·운반 꾸러미)과 작물 3단계 변화가 눈에 띄는지.
5. 첫 수확까지 약 1~2분(플레이어 이동 포함)이 적절한지, 시작 물자 60/40/20 의 여유.
6. 관개 보기(V)·전체 보기(M)의 유용성, 하단 건설 목록의 크기.
7. 기존 schema 1 저장으로 이어하기 → 마을에 복구 현장/시설이 완공 상태로 놓여 있는지, 물자가 한 번만 들어오는지.
