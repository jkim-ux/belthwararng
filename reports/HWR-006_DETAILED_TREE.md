## 구현

`GardenAssets.make("tree")`와 기존 `flower_tree` 이름을 새 모델로 연결했다. 숲 배경과 작업 구역, 재사용 장면 모두 같은 모델을 사용한다. 기존 단순한 수관 코드도 제거했다.

1. S자 줄기·굵은 가지·뿌리를 하나의 연속 표면으로 조형했다. 원통 끝이 드러나는 이음새를 제거하고 굴곡을 따르는 수피의 홈, 작은 옹이 무늬를 넣었다. `models/tree_bark_*.res`가 게임이 사용하는 실제 바이너리 모델이다.
2. 나무당 개별 잎 1,773장. 잎 표면 굴곡·중앙과 측면 잎맥·잎자루·가는 가지와 여러 녹색을 포함한다. 구체 수관, 알파 카드 또는 콘셉트 이미지 평면을 사용하지 않는다.
3. 잎을 하나씩 Node로 만들지 않고 정점 색을 가진 단일 indexed ArrayMesh로 합친다. 3변형 캐시를 재사용하고 양면 불투명 재질을 사용한다. 가까이서 371,380삼각형, 거리 LOD 133,798삼각형(약 64% 감소)이며 후자도 모든 잎을 유지한다.
4. 작업 구역의 매 칸에 큰 수관이 겹쳐 세로 벽처럼 보이던 배치를 줄였다. 숲의 생산 타일과 작업 규칙은 유지한다. 배치·저장·전투 로직은 변경하지 않았다.
5. `scenes/tree_review.tscn`에 동일 모델을 쓰는 단독 검토 장면을 넣었다. 마우스로 회전·확대한다. 일반 마을의 정령, 설치 기능, 16×12 크기와 카메라는 유지한다.

주요 파일: `detailed_tree.gd`, `garden_assets.gd`, `models/tree_bark_*.res`, `source/sculpt_tree_bark.py`, `source/render_tree.py`, `tree_review.gd`, `scenes/tree_review.tscn`, `village_stage_3d.gd`.

## 실행

- Godot에서 `game/project.godot`을 연 뒤 일반 실행 → **마을 바로 테스트**.
- 나무만 볼 때 `game/assets/garden_v1/scenes/tree_review.tscn` → **F6**. 왼쪽 드래그 회전, 휠 확대/축소.
- Godot이 포함된 네이티브 나무 리소스를 읽는다. 게임 실행에 Blender/Python 설치는 필요 없다.
- 모델 원본 재생성과 실제 메시 렌더 방법은 `game/assets/garden_v1/README.md`에 있다.

## 검증 한계와 확인할 부분

- 전체 GUI 플레이 및 대상 Mac의 실제 FPS는 측정하지 않았다. 검사 환경에서 3변형의 최초 메시 생성은 약 5.5초였고, 이후에는 캐시를 공유한다.
- 검토 이미지는 실제 엔진용 모델을 외부 3D 렌더러로 그린 이미지다. Godot GUI 캡처나 새 이미지 생성물이 아니다. 게임 조명·그림자와 미세하게 다를 수 있다.
- 원안의 개별 잎/나뭇결/색 단계와 실루엣을 모델로 옮겼다. 이미지의 회화적 조명과 질감까지 픽셀 단위로 동일하다고 주장하지 않는다.
- 직접 확인할 항목: 나무 단독 확대에서의 잎맥과 이음새, 마을 거리에서의 잎 표현과 프레임, 원안과의 시각적 유사도.
