## 구현한 동작

### 1. HWR-005 R1: 건물 설치 입력 복구 (`scripts/ui/screens/game.gd`, `scripts/village/village_view.gd`)
- **원인(재현 확인)**: `main.tscn` 의 루트 `Game`(전체 화면 Control)이 `mouse_filter` 기본값 STOP 이라 빈 마을 영역의 마우스 이동·클릭을 소비했고, `VillageView._unhandled_input` 에 닿지 않았다. 버튼 클릭은 되지만 미리보기가 포인터를 따라오지 않고 배치가 되지 않는 사용자 보고와 일치한다.
  실제 Viewport 입력 검수(V16)를 수정 없이 실행하면 "건설 목록 클릭 → 배치 모드"는 통과하고 "실제 이동: 미리보기 칸 (2,12) (hover (-1,-1))", "실제 좌클릭: 벌목소 공사 현장 1개"가 실패했다(수정 전 재현 로그 아래 참고).
- **수정**: `Game._ready` 에서 루트를 `MOUSE_FILTER_IGNORE` 로 둔다. Screens/Overlays 는 이미 IGNORE 이며 실제 버튼·패널·모달(자식 Control)은 그대로 입력을 소비한다. 월드 클릭을 `_input` 으로 옮기지 않았고, 모든 Control 을 IGNORE 로 바꾸지도 않았다.
- **HUD 버튼 유지**: 건설 목록 버튼은 `_build_hud` 에서 한 번 만들고 `_refresh_hud` 는 활성·비용 문구·강조색만 갱신한다. 선택 패널은 내용 구조 서명(선택 대상·상태·주민 배정 목록)이 바뀔 때만 다시 만들고 진행 수치는 라벨 글자만 갱신한다. V16 에서 버튼을 누른 채 45프레임(0.5초 갱신 주기 통과) 뒤에 놓아도 같은 버튼 인스턴스로 클릭 1회가 처리된다.
- 마우스 위치는 이벤트의 `position`(창 크기 스트레치 변환이 반영된 1280×720 좌표)을 쓴다. 창 1920×1080(확대 1.5)에서 창 픽셀로 넣은 입력이 같은 칸으로 간다(V16 11번).

### 2. 마을 표시만 단순 카툰 3D (`scripts/village/village_stage_3d.gd`, 신규 ~900줄)
- `VillageView`(Node2D, 입력·HUD·2D 라벨 오버레이) 아래에 `SubViewport`(1280×580, 자동 입력 전달 없음) → `VillageStage3D`(Node3D) 를 두고 `TextureRect`(MOUSE_FILTER_IGNORE)로 표시한다. 입력은 부모가 한 번만 해석한다.
- 직교 `Camera3D`: 수평에서 **20도** 내려다보고 좌우 축과 평행(방위 회전 0). 세로 단위 12(가로 약 26.5단위 = 13칸 → 마을 32칸이 약 2.4화면). 가로만 플레이어를 따라가고(lerp 0.15) 세로 추적은 없다. **M 전체 보기**는 각도를 유지하고 크기만 마을 폭에 맞춘다. 조명은 DirectionalLight 1개 + 옅은 주변광, 그림자 맵 대신 배우 발밑 접지 원판.
- 좌표 계약: 논리 칸 `(qx,qy)` → 바닥 `(2.0·qx, 0, 0.9·qy)`. 바닥 y 는 3D Z, 높이는 3D Y. 주민 `actors.pos`(칸 단위)와 플레이어 `player_pos/48` 을 그대로 변환한다. 화면에서 칸 1개는 가로 96.7px · 깊이 14.9px(V17 측정).
- 마우스 → 칸: 루트 Viewport 위치 → 표시 TextureRect 안 위치 → SubViewport 픽셀 → `Camera3D.project_ray_origin/normal` → Y=0 평면 교차 → 역변환 → floor. 화면 밖·교차 실패는 (-1,-1) = 배치 불가. 별도의 근사 화면 좌표식은 없다.
- 지형은 정점 색 한 메시(강 -0.12 낮춤, 칸마다 옅은 명암 차), 절벽 상자·숲 원뿔 나무·암반 상자·복구 현장 널빤지·출입구 기둥을 얹는다. 장애물: 덤불(구 2개)·나무(원통+구)·바위(상자 2개, 위치 기반 회전).
- 건물 A 잎사귀 텃밭 세트: 농장(흙두둑 3줄·성장 3단계 씨앗/싹/이삭·씨앗·수확 바구니·물 표식), 우물(원통·물 표면·기둥·잎 지붕), 수로(낮은 물길, 젖은/마른 색, 상하좌우 이웃과 이어짐), 작은 보(축소 바람물레 수문: 몸체·회전 물레·출구 물), 벌목소(통나무·기둥·지붕), 채석장(돌 더미·표식), 잎 지붕 작은 집(몸체·큰 잎 지붕·회전 방향 면의 둥근 문), 길, 복구 현장(공사 중 부러진 널빤지 → 완공 포장·등불), 훈련장(기둥·깃발·표적)/보급창(상자 더미). 공사 중은 네 귀퉁이 기둥·자재 더미·진행 높이만큼 차오르는 반투명 판. 상태 서명이 바뀐 건물만 다시 만든다.
- 미리보기: 반투명 건물(허용 초록/불가 빨강 틴트) + 점유 바닥 + 문 칸, 2D 오버레이에 ✓/× 와 이유·비용. R 회전은 기존 `footprint`/`door_cell` 규칙과 같다(V17 회전 4방향 확인). 수로 드래그도 역투영된 칸을 쓴다.
- 선택: 자유 모드 클릭은 건물의 3D 경계 상자를 화면에 투영한 사각형으로 ID 를 찾고(앞쪽 우선, 같은 깊이면 작은 것), 겹치면 같은 자리를 다시 눌러 뒤쪽으로 순환한다. 점유·문·통행 판정은 기존 격자다. 가림 완화: 플레이어·E 대상·미리보기 칸을 화면에서 덮는 **앞쪽 건물만** 알파 0.3 으로 옅게 한다(항상 위에 그리지 않음).
- 이동 속도: 화면 기준 가로 300px/s · 깊이 105px/s 를 카메라에서 측정한 칸/px 로 나눠 논리 속도로 환산한다(V17: 환산값 300/105 확인, 대각선은 정규화 후 축별 적용, 통행 판정은 기존 논리 격자).
- 마을 퇴장(`request_leave`) 시 효과·미리보기·선택을 정리하고 Game 이 뷰(SubViewport 포함)를 지운다. 전투 중 마을 틱·SubViewport 잔류 없음(V18).

### 3. 정령 NPC (`scripts/village/spirit_actor_3d.gd`, 신규)
- 주민 1명당 1개체. 하얀 둥근 몸(구), 작은 검은 눈 2개·짧은 부리, 짧은 회색 날개 2개(어깨 피벗), 몸통 길이 정도의 가느다란 긴 꼬리 2조각(뒤 피벗), 작은 발, 접지 그림자. 인간 팔/손·도구·긴 머리카락 없음. 액세서리는 잎(초기 1번)·푸른 매듭(2번)·짚 매듭(3번)으로 외형만 다르고 능력은 같다.
- 동작은 `VillageSim.work_status()` 의 실제 상태로만 정한다: idle(호흡·눈깜박임·꼬리 흔들림·가끔 주변 보기), move(통통 뛰기, 착지 눌림 7%, 꼬리 지연), windup(도착 후 0.2초 몸 모으고 날개 뒤로), work(0.6초 날개 펴기/0.3초 풀기 반복 + 바람), harvest(실제 수확 이벤트에만 1.2초 점프·날갯짓), blocked(고개 갸웃 + 노란 표식), rest(앉아서 쉼 + 물방울 표식). 점프/부유는 표시일 뿐 막힌 칸을 통과하지 않는다(위치는 항상 시뮬레이션 값).
- 바람: 정령 앞에서 대상 칸으로 흰색/연민트 곡선 리본 3줄(ImmediateMesh 삼각띠) + 작은 알갱이 4개(농사 씨앗 노랑, 물 공급 밭은 물방울 파랑, 정돈은 잎 초록, 공사는 자재색). 작업이 끝나면 정리한다. 물은 우물/보에서 공급될 때만 물방울로 표현하며 바람이 물을 만들지 않는다.
- 수확: 밭의 이삭 6개가 낮게 떠서 바구니로 모이고(1.2초) 정령이 기뻐한다. 연출은 확정된 이벤트에만 반응하며 다시 재생해도 식량이 늘지 않는다(V18).

### 4. '개간'을 정령에게 부탁하는 밭 정돈 (`village_state.gd`, `village_sim.gd`, `campaign_controller.gd`)
- 플레이어의 E 직접 작업(개간·공사·농사)을 모두 제거했다. E 는 인접 장애물 → 정돈 부탁, 인접 건물 → 선택, 출입구 → 지도로.
- 정돈 부탁(`village_request_clear`): 빈손 정령 1명(가장 낮은 ID)에게 예약한다. 같은 자리 연타는 "이미 부탁한 자리", 정돈된 자리·장애물 아닌 칸·잘못된 ID 는 거부, 빈손 정령이 없으면 "빈손 정령이 없음 — 배정 해제하거나 다른 부탁 취소" 이유를 돌려주고 패널에도 표시한다. 취소(`village_cancel_clear`)는 진행량을 남긴다.
- 정령은 장애물에 인접(8방향, 상하좌우 우선)한 **통행 칸**까지 실제 경로로 걸어간 뒤에만 진행한다(초당 1 → 덤불 1·나무 2·바위 3초, 목재 4·석재 3 유지, 완료 시 1회 지급 후 자동 해제). 설 자리가 없는 들판 안쪽은 부탁은 되지만 정령이 막힘(!) 표시로 대기하고 진행하지 않는다(V3). 따라서 빽빽한 들판은 가장자리부터 정돈해야 한다.
- 저장: 주민에 `job_obstacle`(기본 "")을 더하고 `job_kind: "clear"` 로 표현한다(`job_building` 만으로 표현하지 않음). 검증기는 템플릿에 없는/이미 정돈된 대상을 해제하고 오류 목록에 남기며, 한 대상에 두 주민이면 뒤를 해제한다. 진행량은 기존 `clearing` 을 재사용한다. HWR-005 저장(필드 없음)은 그대로 읽힌다(V12). schema 번호는 2 유지.
- 공사/농사는 기존 건물 배정 방식이며, 직접 공사가 사라진 만큼 **주민 공사 속도 초기값 1 → 5 작업량/초**로 조정했다(의도적 수치 변경. 30 공사량 = 정령 6초, 보 60 = 12초). 기존 공사 진행량은 그대로다.
- 유휴 산책: 빈손 정령은 시작 칸 반경 2칸 안의 도달 가능한 칸을 결정적으로 골라 걷고 3~5초 쉰다(실제 위치 이동이므로 그 칸에는 설치가 거부된다). 배정하면 즉시 취소된다. `VillageSim.wander_enabled` 로 끌 수 있다(시연·테스트용).
- UI 명칭: '밭 정돈', '정령에게 부탁', '부탁 취소', '바람으로 짓는 중 N%', '정령 N/7 (빈손 N)'. 내부 자원/건물/거점 ID 는 바꾸지 않았다. dam 의 용량·강가 조건, lumber/quarry/training/depot/repair 의 경제·전투 효과는 그대로다.

## 미수행 검증과 이유

- 실제 키보드·마우스·GPU·소리: 컨테이너에 장치가 없어 루트 Viewport 에 넣은 이벤트와 Mesa 소프트웨어 GL 로 확인했다. 실제 창의 포커스·커서 이동 손맛, 프레임률, 텍스트 가독성은 사용자 확인 항목이다.
- 창 크기 변경은 헤드리스 루트 창을 1920×1080 으로 바꿔 입력 변환을 확인했고, 실제 OS 창 리사이즈·전체화면은 확인하지 못했다.
- 메시 생김새를 검사하는 테스트는 지시대로 만들지 않았다. 외형은 캡처·영상으로만 확인했다.
- 창고 템플릿은 정의·통행·정비/보급창 정령 공사(캠페인 검증)까지 확인했고, 창고에서의 3D 화면 캡처는 하지 않았다(같은 표시 코드).
- 주민 7명이 동시에 좁은 통로를 지나는 겹침 연출, 정령끼리의 충돌 회피는 이번 범위에 넣지 않았다(서로를 막지 않는다).

## 남은 오류 또는 기획과의 차이

- 정돈 작업 위치는 장애물에 **8방향** 인접한 통행 칸으로 해석했다(상하좌우만이면 빽빽한 들판의 첫 줄부터 막히는 경우가 많았다). 들판 안쪽 장애물은 인접 통행 칸이 생길 때까지 부탁만 되고 진행하지 않는다(막힘 표시).
- 유휴 산책은 표시가 아니라 실제 위치 이동이라 산책 중인 정령이 선 칸에는 설치가 거부된다(기존 "주민이 서 있음" 규칙). 시작 칸 반경 2칸으로 제한했다.
- 깊이 압축(칸 깊이 14.9px)으로 세로 방향 통행로가 얇게 보인다. 3×3 농장은 화면에서 290×45px 정도다. 카메라 20°·깊이 0.9 는 `VillageStage3D` 상수로 조정할 수 있다.
- 바람은 삼각띠 리본이라 정령이 대상에 바짝 붙어 있을 때(정돈)는 짧게 보인다. 수로는 직선/모서리/분기를 별도 메시가 아니라 이웃 방향 팔로 표현한다.
- 화면 라벨(이름·진행·이유)은 2D 오버레이 텍스트라 3D 물체에 가려지지 않고 항상 위에 보인다.
- 정령·건물은 코드 생성 메시이며 .glb 교체 지점은 `SpiritActor3D.build()` 와 `VillageStage3D.build_building_visual()` 이다.
- 시작 화면 문구는 HWR-005 그대로다(마을 문구만 도움말·README 에 반영).

## 사용자가 직접 플레이하며 확인할 항목

1. 실제 창에서 건설 버튼 → 빈 땅 이동 → 미리보기가 따라오고 → 클릭으로 설치되는지(이번 R1 의 핵심). 창 크기를 바꿔도 커서와 칸이 맞는지.
2. 낮은 측면 시점의 가독성: 뒤쪽 건물 정면·가운데 밭·앞쪽 통행로가 읽히는지, 깊이(위아래) 이동이 너무 빠르거나 느린지(초기 가로 300 · 깊이 105px/s).
3. 정령의 통통 걷기·날갯짓·긴 꼬리가 귀엽고 작업감이 있는지, 바람 리본·씨앗·물방울이 과하지 않은지, 정령 3명의 액세서리 구분.
4. 밭 정돈을 부탁하는 흐름(E 또는 클릭 → 패널)이 직관적인지, 빈손 정령이 없을 때의 안내가 충분한지, 정령 공사 초당 5(농장 6초)가 적당한지.
5. 겹친 건물 순환 선택과 가림 완화가 자연스러운지, 큰 건물 뒤에서 플레이어가 보이는지.
6. 첫 수확까지의 체감 시간과 산책하는 정령이 설치를 방해하는 느낌이 있는지.
