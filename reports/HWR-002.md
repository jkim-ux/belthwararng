## 미수행 검증과 이유

- **실제 키보드·GPU 플레이**: 컨테이너에 입력 장치와 GPU 가 없다. 손맛(3타 무게감, 1/2타 추적감, 헛침/적중 구분, 기존 반응 유지)과 5~10분 플레이 시간은 사용자 확인 항목이다.
- **렌더 제한 30/60/120 비교**: 고정 물리 60틱 시뮬레이션이라 렌더 프레임과 무관하게 전진 합이 같도록 설계했지만, 소프트웨어 GL 환경에서 실제 프레임 제한 비교는 하지 않았다.
- **사운드**: 프로젝트에 사용 가능한 소리 재료가 없어 휘두름/적중음을 넣지 않았다. 규칙 검증에는 영향 없다.
- **에디터 GUI 열기**: 헤드리스 `--import` 와 실행으로 확인했고 에디터 창을 열어 보지는 않았다.

## 남은 오류 또는 기획과의 차이 (보고 사항)

- **난이도(플레이 확인 필요)**: 단순 연타 조작으로 농촌을 피해 0 으로 9초 만에 이겼다. 근접 적이 접근 중 평타 사거리(95~110)에 들어와 경직 연쇄로 공격을 못 한다. 수치는 기획 초기값 그대로이며 조정은 기획 판단에 맡긴다(예: 근접 적 접근 시 짧은 무적, 예고 중 경직 저항, 체력).
- **대장 30~45초 목표**: 체력 600 / 평타 세트 68 기준 약 9세트가 필요하다. 실제 회피·패턴 대기를 포함한 시간은 플레이로 측정해야 한다.
- **동시 공격자 규칙의 대장 적용**: 대장은 단독이라 공격 허가를 사용하지 않는다.
- **같은 틱 다중 타격 규칙**: "마지막 적용 순서(플레이어 → 동료 → 적 순, 투사체는 근접 판정 뒤)"를 채택했다. 현재는 주인공 평타끼리 같은 틱에 겹치지 않으므로 화살(경직 0)과 평타의 조합만 실제로 발생한다.
- **동료 궁수의 밀림**: 피격 시 적 공격 밀림의 60% 를 적용했다(기획은 "짧은 경직/밀림"만 명시). 수치는 `archer_companion.gd` 에 있다.
- **화면 조작**: 메뉴는 Godot 기본 UI 초점 규칙(방향키·Enter)과 마우스를 쓴다. 게임패드 매핑은 없다.
- 기획 문서(v0.3, COMBAT_FEEL, CAMPAIGN_SYSTEMS)와 충돌하는 구현은 발견하지 못했다. 스토리 문구·동료 이름·전경 표현은 기획 초기안을 그대로 썼고, 사용자 확정 요구(사무라이, 첫 마을 반격, 5챕터, 챕터별 NPC 해금, 마을 관리, 모멘텀 개선)와 기획자가 정한 수치(12/18/30, 600, 100/20 등)를 구분해 데이터 리소스에 두었다.

## 사용자가 직접 플레이하며 확인할 항목

- 수련장에서 F2 로 기존/새 프로필을 번갈아 3연타: **3타가 가장 무겁게 느껴지는가**, **1/2타가 맞은 적(밀림 표적·근접 적)을 따라가며 이어지는가**, **헛쳤을 때와 맞혔을 때가 구분되는가**, **이동·회피 반응이 M1 과 같은가**.
- 새 게임 → 농촌 → 정비/훈련장 → 창고 → 보급창 → 초소 → 아야 → 농촌 재도전: 흐름이 끊기는 곳, 관리 화면의 이해도, 첫 챕터 플레이 시간(목표 5~10분).
- 대장의 두 패턴이 피할 만한지, 30~45초 안에 끝나는지. 근접 적 2×2 / 3×2 가 너무 쉬운지(위 난이도 보고 참고).
- 아야의 존재감: 뒤에서 따라오고 화살이 실제로 맞는지, 주인공 연타를 방해하지 않는지, 이탈 뒤 다음 출정에서 돌아오는지.
- 저장: 종료 후 이어하기로 관리도·시설·해금·선택 동료가 유지되는지.
