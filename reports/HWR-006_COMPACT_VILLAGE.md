## 적용

1. 농촌·창고 마을 모두 32×24 → **16×12칸**. 이동·설치·출입구·복구 현장·보·벌목/채석 구역을 새 크기로 재배치했다. 시작 면적은 768 → 192칸이다.
2. 직교 카메라 크기 12 → **8.5**. 동일 화면에서 정령이 약 1.41배 크게 보인다. 낮은 측면 각도 20도와 가로 추적, M 전체 보기를 유지한다. 카메라의 겨냥 높이도 조절해 배경 수관과 마을 입구가 화면 안에 들어온다.
3. 두 시작 지형에서 개간 장애물을 제거했다. 농장 `placement`는 `land`로 바꿨다. 빈 일반 땅에 3×3 밭을 바로 놓을 수 있으며 물 공급과 정령 배정은 여전히 필요하다. 강·예약 통행로·다른 건물·경계 밖에는 설치할 수 없다.
4. 실제 `VillageStage3D`에 풀밭, 겹친 낮은 언덕, 둥근 나무, 나무 울타리, 작은 꽃을 붙였다. 배경은 표시 전용이며 충돌체나 작업 대상이 없다. 바닥 삼각형의 앞면 방향과 정점 색의 선형 변환도 고쳐 주변 잔디와 명도를 맞췄다.
5. 기존 저장은 `layout_version`으로 한 번만 이전한다. 복구·특수 시설부터 통행 규칙을 확인해 작은 마을로 옮긴다. 들어가지 않는 건물은 **보관 N · 무료 재배치**로 건설 목록에 남는다. 같은 버튼으로 비용 없이 복원하며 ID·완공 상태·공사/수확 진행량을 유지한다. 주민 수, 자원, 시설 효과와 일회성 기록은 다시 지급하지 않는다.
6. 이전 배치 기록을 저장 안에 보존하고 원본 저장은 `.large-village.bak`로 별도 보존한다. 저장 실패 시 후보 상태를 재시도하며 보관 건물이나 자원을 먼저 소모하지 않는다. 공간 재배치 후 물길은 다시 연결해야 할 수 있다. 보관된 건물의 주민 작업은 해제되므로 재배치 후 배정한다.

## 실행

```sh
godot --path game -- --village-test
```

또는 시작 화면의 **마을 바로 테스트 (전투 없이 · 별도 저장)**. 기존 일반 캠페인 저장과 테스트 저장은 분리되어 있다.

- Godot 프로젝트 import: 스크립트 오류 없음.
- 현재 마을 검증: **102 통과 / 0 실패**. 16×12 템플릿, 모든 건물 종류의 설치 자리, 필수 통행, 일반 땅 농장, 경계/길 보호, 정령 도착 후 공사·물길·수확, 저장 왕복, 건물 35개가 있는 옛 저장의 이전·보관, 무료 재배치, 저장 실패·재시도, 실제 Viewport 마우스 클릭, 직교 좌표 왕복, 테스트 진입과 일반 저장 분리를 확인했다. 이 수에는 선택적 실제 장면 GLB 내보내기 1개가 포함된다(환경 변수 없이 실행하면 101개).

- 실제 게임 장면의 메시와 카메라를 Godot에서 내보내 외부 메시 렌더러로 구도를 확인했다. GUI 화면 캡처로 간주하지 않는다.


## 남은 확인과 반영

- 실제 Godot GUI 플레이와 기기별 프레임 측정은 이 환경에서 수행하지 않았다. 사용자는 가까운 시점의 이동·배치 감각과 배경 명도를 확인하면 된다.
- 기존 정령 디자인은 그대로 사용한다. 이 작업에 새 3D 바이너리 모델 패키지는 필요하지 않다.
- 소스·지형·검증·실행 안내·이 보고서를 현재 원격 작업 브랜치에 함께 반영한다. 완료 커밋의 실제 해시는 Git 기록과 최종 응답에서 확인할 수 있다.
