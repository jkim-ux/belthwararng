## 시작
사용자는 전투 느낌과 일부 마을 구현을 확인했으나 일반 전투가 쉽고 짧다고 평가했다. HWR-002 보고의 농촌 9초/무피해 기록도 참고한다.
확인한 최신 코드: claude/upbeat-mayer-r3t54f의 13e8581a5916ee35cf6d90658ed7d026e47c5e95, PR #1. main은 기획 중심이다. 실제 최신 구현과 미커밋 변경을 확인해 이어서 작업하며, 기준 커밋으로 강제 복원하지 않는다.
기존 이동·평타 모멘텀·마을·동료·저장을 보존하고 최신 main 문서를 안전하게 반영한다. 스토리 작업 지시와 산출물은 별도이며 이번에 다시 집필하지 않는다.

## 구현 순서
1. 던전/방 정의와 런타임 상태, 방 정리/거점 승리 분리, HP/대기시간을 유지하는 문 이동부터 구현한다.
2. 같은 연결 데이터를 사용하는 우측 상단 미니맵을 구현한다. 현재/미방문/정리/보스/보물/문 상태와 웨이브 표시를 확인한다.
3. 적 궁수와 예고 사격, 투척병과 고정 착탄점·바닥 불을 구현한다. 일반 방마다2웨이브, 근접2/원거리1 공격 허가, 활성+예약 화염 최대2.
4. 보물 상자1회 개봉·회복·보류 군자금, 각 거점 보스1명, 보스 승리 시 한 번의 거점 해방/저장으로 연결한다.
5. 농촌/창고/초소 세 거점에 적 조합을 적용하고 실제 시간·피해·문/미니맵·동료를 검수한다.

단계별로 실행 가능한 커밋을 남기고 순서대로 완료한다. 상세 초기값·연결도·적 배치·판정 예외·보상·인수 시나리오는 DUNGEON_COMBAT가 기준이다.
보스방은 보스1명, 입구/보물방은0웨이브, 일반 방은2웨이브다. 새로운 출정과 다음 방 진입을 같은 초기화 함수로 처리하여 체력을 채우지 않는다.

## 검수와 보고
DUNGEON_COMBAT의10개 검수 항목과 기존 전투/캠페인 검증을 실행한다. 기존 '농촌2묶음이면거점승리' 테스트는 새 방/보스 구조에 맞춰 바꾸되 과거 모멘텀/저장 검증을 무의미하게 삭제하지 않는다.
추가로 실제 화면에서 우측 상단 미니맵, 갈림길→상자→재방문, 투척 예고→착탄→피해, 보스 처치→결과를 확인한다. 가능하면 해당 화면/짧은 시연을 남긴다.
실제 키보드 플레이 불가 시 자동 입력 검증과 사용자 확인 항목을 구분한다. 자동 승리 시간 하나를 손맛 검증으로 취급하지 않는다.
reports/HWR-003.md에는 실제 기준 커밋/엔진, 구현 단계, 실행법, 변경 파일, 실제 검증 결과, 미수행, 신규 수치/변경 이유, 거점·방별 전투 시간/받은 피해/상자 사용, 남은 문제, 원격 반영 여부를 기록한다.
마을 저장은 기존 사용자 데이터를 보존하고 테스트는 별도 경로로 수행한다. run 중간 저장은 이번에 없다. 저장 형식을 바꿔야 하면 이전 상태를 유지하는 이전 처리를 한다.
허용된 작업 브랜치로 커밋·푸시, 필요하면 초안 PR을 갱신한다. main 자동 병합은 하지 않는다.

이번에 만들지 않을 것: 챕터2~5 전투, 추가6스킬, 랜덤 맵, 열쇠, 복잡한 장비/드롭, 새로운 스토리 분기, 최종 미술. 기존 범위에 새로운 적과 방 탐색을 완성하는 데 집중한다.
