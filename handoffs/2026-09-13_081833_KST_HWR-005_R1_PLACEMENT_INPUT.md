## 1. 최우선 원인 후보: 전체 화면 Game Control의 입력 소비
- game/scenes/main.tscn의 루트 Game은 전체 화면 Control이며 mouse_filter를 지정하지 않았다.
- game/scripts/ui/screens/game.gd의 Game._ready는 Screens/Overlays만 MOUSE_FILTER_IGNORE로 설정하고 Game 자신은 변경하지 않는다.
- VillageView는 Node2D이며 마우스 이동/좌클릭/우클릭을 _unhandled_input에서 받는다. 건설 미리보기의 hover_cell 갱신도 여기에 있다.
- 따라서 실제 UI 버튼 클릭은 작동해도, 빈 마을 영역의 마우스 이동과 클릭은 전체 화면 Game Control이 소비하여 배치까지 도달하지 않을 가능성이 높다.
근거: [Godot Control 입력 규칙](https://docs.godotengine.org/en/stable/classes/class_control.html#enum-control-mousefilter). 기본 mouse_filter는0(STOP)이고 해당 입력을 처리 완료로 표시한다.

실제 시작 장면을 띄워 건설 버튼→빈 마을 영역 이동→유효 위치 클릭까지 재현하고 이벤트 전달을 확인한다. 루트 Game을 입력을 가로채지 않는 컨테이너로 설정하는 작은 수정부터 적용한다(예: Game._ready의 mouse_filter = Control.MOUSE_FILTER_IGNORE 또는 같은 씬 속성).
실제 버튼·건설 목록·선택 패널·모달은 계속 UI 입력을 처리해야 한다. 모든 Control을 IGNORE로 바꾸거나 월드 클릭을 _input으로 옮겨 UI 위에서도 건물을 놓게 만드는 수정은 피한다.
MOUSE_FILTER_PASS와 IGNORE를 동일하게 취급하지 말고 Viewport→GUI→_unhandled_input 경로 전체를 확인한다.

## 2. 함께 확인할 클릭 안정성
VillageView._process는 약0.5초마다 _refresh_hud를 호출하며, 이 함수는 건설 목록과 선택 패널의 버튼을 queue_free 후 다시 만든다. 버튼을 누른 상태에서 갱신이 겹치면 놓기 전에 버튼이 교체되어 클릭/포커스가 유실될 수 있다.
목록과 버튼은 유지하고 글자·활성 상태·숫자를 갱신하거나, 목록 구조가 바뀔 때만 재구성한다. 드래그/버튼 누름 도중 무조건 위젯을 제거하지 않는다. 이 항목도 코드상 위험이며 재현 결과를 기록한다.
마우스를 움직이지 않고 캐릭터/카메라만 움직였을 때 미리보기 칸과 실제 클릭 칸이 일치하는지 확인한다. 실제 포인터 위치를 사용하되 도움말/저장 실패 UI 아래에 배치를 흘리지 않는다.

## 3. 기존 시험이 놓친 부분
tests/run_village_tests.gd의 test_v15_game_screens_village는 begin_place/confirm_place/_left_press/_left_release를 직접 호출한다. 이는 설치 모델과 함수를 검증하지만, 사용자의 클릭이 GUI를 거쳐 해당 함수에 도달하는지는 확인하지 못한다.
기존 모델 검증을 유지하면서 실제 Game 씬을 사용하고 Viewport 입력 경로로 마우스 이동·누름·놓기를 넣는 회귀 검증을 추가한다. 테스트에서만 루트 mouse_filter를 바꾸거나, 설치 함수를 직접 호출한 결과를 실제 클릭 성공으로 집계하지 않는다.

| 재현 | 합격 기준 |
| --- | --- |
| 건설 목록 클릭→월드 이동 | 해당 건물 선택·포인터 위치로 미리보기 이동 |
| 유효 칸 좌클릭 | 공사 현장1개 생성, 비용1회 차감 |
| 불가 칸 좌클릭 | 불가 이유 표시, 건물/자원 변화0 |
| UI 위 클릭/도움말·저장 실패 창 | UI만 동작, 뒤쪽 땅 설치·선택0 |
| 버튼 누름 후 HUD 갱신을 지나 놓기 | 클릭1회, 선택/배정 유지 |
| 수로 드래그·우클릭 취소 | 실제 누름/이동/놓기로 묶음 설치, 취소 비용0 |
| 카메라 추적/전체 보기/창 크기 변경 | 미리보기와 실제 확정 칸 일치 |
| 시작·지도·결과·전투 일시정지 | 기존 버튼/키보드 탐색과 입력 차단 유지 |

현재 테스트의 유효한 벌목소 위치(농촌2,12) 등을 준비 상태로 활용하되 클릭 좌표는 실제 카메라/화면 변환으로 얻는다. 땅/재료/주민/통로 조건 때문에 실패한 경우에는 입력이 누락된 경우와 구분해서 기록한다.
