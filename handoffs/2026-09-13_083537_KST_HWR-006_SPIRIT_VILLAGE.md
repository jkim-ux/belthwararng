## 1. 사용자 결정과 범위

스토리 집필은 보류한다. 이번 임시 전제는 '주인공이 흰 오목눈이처럼 생긴 바람 정령들의 마을에 왔다'까지다. 새 전쟁사·챕터 줄거리·주인공 외형을 만들지 않는다. 기존 전투, 스킬, 던전, 캠페인 진행, 동료와 저장은 회귀 검증 대상으로 유지한다.

마을은 가로로 길게 걷고 화면 안팎으로도 움직이는 벨트스크롤 공간이다. 이동·건설·관개 확인 중 모두 같은 낮은 측면 카메라를 쓴다. 탑다운/아이소메트릭 마을을 최종 결과로 제출하지 않는다.

이번 구현은 A '잎사귀 텃밭'을 임시 기본 외형으로 진행한다. B/C는 선택을 위한 콘셉트이며 세 테마를 모두 구현하지 않는다. 그림 확정을 기다릴 필요 없이 아래 단순 메시 구성과 동작부터 만들 수 있다.

## 2. 시작할 코드와 먼저 해결할 오류

작성 시 확인: main 2506243에는 004가 병합되어 있다. 005 코드는 PR #2, claude/magical-bohr-2eljuj의 a6120095에 있으며 004를 포함한다. 작업 시작 시 최신 상태를 다시 확인한다. 기존 005가 있는 작업 브랜치에 최신 지시를 반영하거나, 그 구현을 기반으로 후속 브랜치를 만든다. main만 보고 마을 시스템을 다시 만들지 않는다. PR 병합은 별도 사용자 요청을 따른다.

사용자는 005에서 실제 건물 설치가 안 된다고 보고했다. 이 오류는 해결 확인 전이며 006에 이월한다.

1. 005 R1의 실제 클릭 재현부터 실행한다. Game 루트 Control의 기본 마우스 소비와 0.5초마다 재생성되는 HUD 버튼을 확인한다.

3. 실제 Game 장면의 Viewport로 마우스 이동·누름·뗌을 보내 건설 팔레트 선택→바닥 배치까지 검증한다. confirm_place() 직접 호출만으로 통과 처리하지 않는다.
4. 아래 3D 표시 계층을 붙인 뒤 같은 입력 검사를 다시 통과시킨다.

## 3. 구현 방식: 마을 표시만 단순 카툰 3D

현재 Godot 프로젝트의 VillageView(Node2D), VillageSim, CampaignController 구조를 활용한다. VillageSim의 격자·점유·통행·작업·경제와 CampaignController의 검증/저장 경로를 단일 원본으로 둔다.

마을 표시용 SubViewport 하나에 Node3D 장면, 직교 Camera3D, 간단한 조명, NPC/농장 메시를 둔다. 부모 VillageView는 입력과 HUD를 관리한다. 게임 전체를 3D로 이식하거나 3D 물리/내비게이션으로 마을 시뮬레이션을 중복 구현하지 않는다.

- 표시 TextureRect는 MOUSE_FILTER_IGNORE. 부모에서 입력을 한 번 해석한다. SubViewport에 자동 입력 전달까지 겹쳐서 두 번 설치하지 않는다.
- 기존 GL Compatibility에서 동작하는 단색 재질과 기본 조명을 우선한다. 런타임 외부 모델링 도구·유료 에셋·외부 다운로드가 없어도 실행 가능해야 한다.
- 첫 메시들은 구/타원체/상자/원통/간단한 잎 메시로 만든 재사용 장면이다. 향후 .glb로 교체할 수 있도록 논리 actor ID와 시각 장면을 분리한다.
- 기본 조명 1개, 부드러운 명암, 작고 옅은 접지 그림자. 털 시뮬레이션, 반사/굴절 온실, 복잡한 후처리, 사실적 깃털은 이번 제작 목록에 없다.
- 주인공은 기존 임시 외형을 빌보드 등으로 재사용한다. 필요 시 같은 역할의 단순 임시 표시를 쓴다. 새 사무라이 디자인이나 의상을 제작하지 않는다.
- 마을 퇴장 시 표시 장면·카메라·효과를 정리하고 시뮬레이션 틱 중복/전투 입력 누수를 방지한다.

제안 파일 분리: village_view.gd(입력/HUD), village_stage_3d.gd(표시·카메라·좌표 변환), spirit_actor_3d.gd(외형·동작), farm_visual_3d.gd(작물 단계·설비·효과). 실제 저장소 관례에 맞춰 이름은 조정 가능하다.

## 4. 시점·좌표·설치 계약

### 화면

1280×720 기준 기존 상단 44px/하단 96px를 제외한 마을 영역을 사용한다. 긴 가로 거리, 뒤쪽 건물 정면, 가운데 작업 밭, 앞쪽 통행 공간을 읽을 수 있게 배치한다. 건물 높이가 바닥 타일보다 먼저 눈에 들어와야 한다.

직교 카메라는 수평에서 약 20도 내려다보며 좌우 축과 평행하게 고정한다. 45도 대각선 방위 회전은 하지 않는다. 화면에 지붕 윗면보다 건물 정면이 크게 보이게 한다. 일반 화면은 가로 약 2~3화면 길이의 마을을 스크롤하고, 카메라 세로 추적은 없거나 제한적이다. M 전체 보기에서도 각도는 유지하고 줌만 변경한다.

### 기존 데이터 보존

32×24 논리 격자와 저장된 x/y/회전/건물 ID를 그대로 사용한다. 기존 48px 좌표와 주민의 칸 단위 좌표를 섞지 않는다. 표시에서만 가로 폭을 넓히고 깊이를 압축한다.

초기 표시 변환 예시(조정 가능한 값):
- 논리 칸 좌표 q=(qx,qy) → 3D 바닥 위치 (2.0*qx, 0, 0.7*qy).
- 주민 actors.pos는 이미 칸 단위다. player_pos는 48로 나누어 칸 단위로 바꾼다.
- 바닥 y는 3D Z, 모델 높이/떠오름은 3D Y다. 떠오르는 몸과 바닥 위치/접지 그림자를 분리한다.
- 카메라는 +Z 쪽에서 -Z를 보며 내려다본다. 논리 y가 커지면 화면 아래/앞쪽으로 온다.
- 논리 셀 모서리 네 점으로 실제 3D 배치 바닥을 만든다. NPC 메시를 격자 종횡비대로 찌그러뜨리지 않는다.

마우스: 루트 Viewport 위치→표시 TextureRect 내부 위치(여백·확대율 반영)→SubViewport 픽셀→Camera3D 레이→Y=0 바닥 평면 교차→역변환→floor로 셀 결정. 화면 바깥/레이 교차 실패는 배치 불가다. 실제 카메라 변환을 사용하고 별도의 대충 맞춘 스크린 좌표식을 추가하지 않는다.

설치 모드에서는 건물 표면이 아닌 바닥 레이로 위치를 정한다. 선택 모드에서는 보이는 건물 메시/선택 영역으로 ID를 찾고, 뒤쪽 건물은 가림 완화/순환 선택으로 접근 가능하게 한다. 시각 선택용 콜라이더를 쓰더라도 게임 점유·문/작업 위치 판정은 기존 격자가 담당한다.

미리보기는 반투명 건물+점유 바닥+작업 위치 표시다. 색과 허용/불가 아이콘·이유를 함께 보여준다. R 회전은 기존 footprint 및 door_cell 규칙과 일치한다. 수로 드래그도 역변환된 셀을 사용한다. 카메라 이동·전체 보기·창 크기 변경 후에도 커서와 설치 위치가 맞아야 한다.

기존 건물을 다른 칸으로 몰래 옮기거나 저장을 초기화하지 않는다. 새 게임에서만 템플릿을 다듬을 경우 버전을 구분하고 기존 지형·장애물 ID를 유지하는 경로를 제공한다. 006 첫 구현은 기존 템플릿의 표시 전환으로 충분하다.

이동 속도는 화면상 가로 약 280~320px/s, 깊이 약 90~120px/s를 초기 조정 목표로 삼는다. 논리 좌표 이동으로 환산하고 대각선 속도/통행 판정을 유지한다. 모델 방향은 이동/작업 대상을 향하되 카메라가 따라서 회전하지 않는다.

큰 건물 뒤에서 조작 대상이 가려지면 해당 가림 메시만 옅게 하거나 윤곽을 표시한다. 건설 모드에서는 지붕/전경 장식 가림을 완화한다. 모든 메시를 항상 위에 그려 깊이를 없애지 않는다.

## 5. 정령 NPC와 살아 있는 농장

기존 주민 한 명당 정령 한 개체를 만든다. 기존 주민 ID·배정·인원·주택 해금은 보존한다. 초기 주민 3명은 외형 변주를 갖되 파종/관수/수확을 할 수 있는 능력은 공통이다. 전문 직업 세 개나 추가 노동력 세 개를 새로 요구하지 않는다.

공통 외형: 하얀 둥근 몸, 작은 검은 눈과 짧은 부리, 짧은 회색 날개, 몸통 길이 정도의 가느다란 긴 꼬리, 작은 발. 잎/물방울/짚 매듭 액세서리만 교체한다. 얼굴 앞에 긴 머리카락·인간 팔/손·도구 파지를 추가하지 않는다.

최소 동작:
| 상태 | 눈에 보이는 동작 | 논리 조건 |
| --- | --- | --- |
| idle | 호흡, 눈깜박임, 꼬리 흔들림 | 작업 없음 |
| move | 짧게 통통 뛰거나 지면 가까이 떠서 이동 | 실제 actors.pos/경로 변화 |
| windup | 몸을 모으고 날개를 살짝 뒤로 | 작업 위치 도착 후 |
| work | 날개를 펴고 곡선 바람을 밭/대상으로 보냄 | 유효한 작업 중 |
| harvest | 이삭/열매가 낮게 떠서 바구니로 모이고 짧게 기뻐함 | 실제 수확 완료 이벤트 |
| blocked/rest | 고개 갸웃/앉아서 쉼, 짧은 상태 아이콘 | 길 막힘·물 부족·배정 없음 등 |

바람은 흰색/연민트 곡선 2~3줄, 씨앗·잎·물방울 소량으로 표현한다. 과한 회오리로 NPC와 작물을 가리지 않는다. 점프/부유는 표시 애니메이션이며 막힌 칸을 통과하는 비행 능력이 아니다. 유휴 산책은 도달 가능한 주변 몇 칸 안에서 실행하고, 배정 시 즉시 취소한다.

농장 한 곳의 기존 생산 진행률을 세 시각 단계에 연결한다: 씨앗이 골에 들어감→물방울과 바람에 싹/잎이 흔들림→익은 작물이 바구니로 모임. 기존 30초/6식량을 초기 유지한다. 효과가 없어도 생산 규칙이 정상이어야 하고, 효과를 다시 재생해도 보상이 늘어나면 안 된다. 물 공급·도착한 일손이 없으면 기존 진행 조건에 따라 멈추고 화면에도 이유가 보인다.

A 기본 제작물: 잎 지붕 작은 집 1종, 낮은 텃밭 1종(성장 3단계), 우물 1종, 낮은 수로 직선/모서리/분기, 씨앗 바구니, 수확 바구니, 작은 바람 표식. 우물의 물을 정령 바람이 낮게 날려 밭에 뿌린다. 바람이 물을 무에서 생성하는 규칙은 추가하지 않는다.

## 6. '개간'을 정령에게 부탁하는 밭 정돈으로

플레이어가 E를 계속 눌러 직접 나무를 베고 곡괭이질하는 연출을 바꾼다. 플레이어는 배치하고 작업을 부탁하며, 정령이 이동해서 바람으로 잎을 치우고 돌/떨어진 가지를 모은다. 거대한 벌목 현장이나 토목 댐이 첫 농장의 중심이 되지 않게 한다.

- 장애물 근처 E 또는 해당 대상의 '정돈 부탁' 버튼으로 유휴 정령 1명에게 작업을 예약한다. 한 번 요청하면 E를 놓아도 계속한다. 유휴 정령이 없으면 배정 해제 방법과 이유를 표시한다.
- 이 작업은 실제 주민 배정을 점유한다. 바닥의 도달 가능한 인접 작업 칸까지 이동한 후에만 진행한다. 기존 장애물 제거 시간(덤불1/나무2/바위3초)과 자원(0/목재4/석재3)은 유지한다.
- 유휴 산책/농사/공사와 중복 배정하지 않는다. 예약 중 취소·재배정·막힌 길·다른 작업의 선행 제거·퇴장/재입장을 처리한다.
- 005의 job_building만으로 장애물 대상을 표현하지 말고 정돈 대상 ID를 선택적으로 저장한다(예: job_kind=clear, job_obstacle=기존 장애물 ID). 기존 저장에는 기본값을 채우고 검증기·복사·저장 경로를 함께 갱신한다. 진행량은 기존 clearing 데이터를 재사용한다.
- 공사/농사는 기존 건물 배정 방식을 사용한다. E 직접 작업 가산은 제거한다. 직접 공사가 사라지는 만큼 주민 공사 속도의 초기값을 1→5 작업량/초로 조정한다. 기존 공사 진행량은 유지한다. 이는 이번 의도적 수치 변경이며 보고에 기록한다.
- UI 명칭은 '밭 정돈', '정령에게 부탁', '바람으로 짓는 중' 등 짧게 바꾼다. 내부 자원/건물/거점 ID는 바꾸지 않는다.
- dam의 기존 물 용량/강가 설치 조건은 유지하고, 외형은 작은 바람물레 수문으로 축소 표현한다. lumber/quarry/training/depot/repair 등 기존 시설도 간단한 3D 표식을 제공하여 안 보이는 장애물이 되지 않게 한다. 이들의 경제/전투 효과를 재설계하지 않는다.

신규 전용 화폐, 계절, 번식, 배고픔/사망, 작물 품종 경제, 오프라인 수익, 새로운 챕터는 이번 범위에 포함하지 않는다.

## 7. 구현 순서와 합격 기준

1. 005 R1 입력 수정 → 실제 창에서 팔레트 선택/배치/선택/수로 드래그 확인.
2. 임시 메시로 측면 카메라와 기존 저장 배치 표시 → 걷기/가림/역투영 설치 확인.
3. 정령 1개체의 실제 작업 상태와 이동·바람·수확 연결 → 3명 외형 변주.
4. A 농장·우물·수로·집 적용 → 정돈 요청과 저장 호환 → 전투 왕복 확인.

| 검수 | 통과 조건 |
| --- | --- |
| 시점 | 일반/건설/M 전체 보기 모두 낮은 측면, 가로 스크롤과 화면 안팎 이동 |
| 실제 설치 | 팔레트 버튼 후 마우스로 빈 칸 배치 성공, UI 클릭은 월드 설치를 유발하지 않음 |
| 역투영 | 카메라 좌/중/우, 1280×720 및 다른 창 크기, 전체 보기에서 동일 셀에 미리보기/실제 배치 |
| 통행/회전 | 문 앞 접근 가능, 통로 차단 거절, 회전 후 작업 위치와 그림 일치 |
| 정령 작업 | 배정된 실제 주민이 도착해 날갯짓, 막힌 길/물 부족 중 거짓 농사 연출 없음 |
| 정돈 | 요청 후 정령 이동/자원 1회 지급, 연타·취소·로드로 중복 지급 없음 |
| 농사 | 물+일손 조건에서 성장 3단계와 수확, 기존 식량 보상과 화면 연출 일치 |
| 저장 | 005 저장의 자원/배치/회전/주민/작업/진행 보존, 신규 정돈 요청 저장/재입장 정상 |
| 왕복 | 마을→캠페인→전투→마을, 전투 조작과 기존 보상 정상, 카메라/효과/틱 잔류 없음 |

좌표 변환 왕복과 실제 Viewport 입력, 정돈 배정/보상/이전 저장은 자동 검증을 추가한다. 기존 마을·캠페인·전투 검증을 실행한다. 메시 생김새를 검사하는 구현 복제 테스트는 만들지 않는다.

reports/HWR-006.md에는 기준 브랜치/커밋, 변경 파일, 실행 방법, 테스트 명령·실제 결과, 알려진 제한을 남긴다. 같은 실제 게임 실행에서 측면 전체 모습·배치 성공·정령 작업 스크린샷과 15~30초 이동/바람 농사 영상을 제출한다. 캡처가 불가능하면 이유와 미검증 항목을 기록한다. 콘셉트 그림을 실행 화면으로 제시하지 않는다.
