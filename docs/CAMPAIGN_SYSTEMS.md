# 마을·동료·저장 규칙 — v0.4
작성: 2026-09-12 16:07:01 KST / 2026-09-12T07:07:01Z
기획 기준: [GAME_DESIGN v0.4](GAME_DESIGN.md). 방/원거리 적/보물은 [DUNGEON_COMBAT](DUNGEON_COMBAT.md)를 함께 따른다.
수치는 첫 챕터의 검증용 초기값이며, 변경 시 실제 값과 이유를 보고한다.

## 1. 상태를 구분한다
ChapterDef: 챕터 ID, 표시명, 선행 챕터, 필수 거점 ID, 보상 동료 ID, implemented.
SiteDef: 거점 ID, 챕터 ID, 종류 village/fort, 선행 조건, 전투 정의, 최초/반복 보상, implemented.
CompanionDef: ID, 표시명, 역할, 해금 챕터, implemented. 처음에는 궁수만 구현한다.
정의 Resource와 실행 중 상태는 분리한다. 필요 이상으로 범용 플러그인 구조를 만들지 않는다.

상태 표시는 세 층이다.
- 소유: 점령 중 / 해방 완료.
- 진입 가능 여부: 선행 조건 충족 여부와 콘텐츠 구현 여부에서 계산한다.
- 마을 관리도: village에만 존재. 미해방 0, 첫 해방 40, 정비 후 60.

고개 초소는 군사 거점이므로 관리도/논밭/정비 버튼이 없다. 초소에도 마을 정비가 필요했던 v0.2 문구를 대체한다.
콘텐츠 미구현과 진행 잠금을 구분해 설명한다. 챕터1이 끝나도 챕터2에 implemented=false면 진입 불가다. 단순히 '잠김'만 보여 무엇이 필요한지 모르게 하지 않는다.

## 2. 첫 챕터의 거점과 던전
농촌(ch1_farm)은 새 게임에서 진입 가능, 창고(ch1_store)는 농촌 해방/관리도60, 초소(ch1_pass)는 창고 해방/관리도60에 열린다. village/fort 구분과 기존 저장 ID는 유지한다.
각 거점은 입구·일반 전투방3개·선택 보물방·보스방의 고정 던전으로 확장한다. 일반 방은 각각2웨이브다. 방 연결·적 배치·미니맵·화염·보스 초기값은 DUNGEON_COMBAT가 기준이다.
각 거점의 마지막 보스를 처치해야 그 거점의 최초/반복 보상과 해방을 확정한다. 농촌/창고 보스는 해당 거점 해방, 초소 보스는 추가로 챕터1 클리어/아야 해금이다. 방별로 apply_victory를 호출하지 않는다.

## 3. 마을 복구와 군자금

| 행동 | 조건 | 비용/보상 | 효과 |
| --- | --- | --- | --- |
| 각 거점 최초 승리 | 아직 미해방 | +100 | village면 관리도40; fort에는 관리도 없음 |
| 각 거점 재도전 승리 | 이미 해방 | +20 | 점령/관리/해금 초기화 없음 |
| 농촌/창고 정비(각1회) | 해당 마을 해방, 미정비 | -40 | 해당 관리도40→60; 다음 거점 진입 조건 |
| 농촌 훈련장(1회) | 농촌 관리도60, 미구매 | -60 | 주인공 기본 공격력+5% |
| 창고 보급창(1회) | 창고 관리도60, 미구매 | -60 | 주인공 최대 체력+10 |
| 초소 관리/정비 | 해당 없음 | 해당 없음 | UI에 구매 버튼을 만들지 않음 |

새 게임 군자금0. 출정 비용은 없고 패배로 보유 자금을 잃지 않는다. 두 마을의 정비는 경로를 안전하게 복구한다는 첫 챕터 안내이고, 시설 구매는 선택 사항이다.
새 게임에서 반복 사냥 없이 정비와 두 시설을 모두 구매할 수 있다. 아래 계산과 기존 인수 시나리오는 선택 상자를 열지 않은 기본 보상 기준이다. 개봉했다면 성공한 출정당30이 추가된다.

| 순서 | 군자금 |
| --- | --- |
| 농촌 첫 승리 | 100 |
| 농촌 정비 + 훈련장 | 100-40-60=0 |
| 창고 첫 승리 | 100 |
| 창고 정비 + 보급창 | 100-40-60=0 |
| 초소 첫 승리 | 100 |
| 해방된 거점 재도전 1회 승리 | 120 |

정비만 하고 시설 구매를 미뤄도 진행된다. 부족한 돈/중복 구매/미해방 거점에 대한 호출은 UI와 상태 변경 함수 양쪽에서 거부하며 자금이나 효과가 바뀌지 않는다.
관리도와 소유가 재도전 승리로 40으로 되돌아가지 않는다. 시설을 같은 종류의 모든 마을에 복제하여 +5%가 끝없이 쌓이게 하지 않는다.
출정 시 영구 효과는 저장된 구매 플래그로 계산한다: 공격력=기본값×(훈련장 구매 시1.05, 아니면1), 최대체력=기본값+(보급창 구매 시10, 아니면0). 기존 damage rounding은 유지한다. 동료 능력에는 이번에 주인공 시설 보너스를 적용하지 않는다.
출정 시 주인공과 동료 체력을 최대값으로 채우고 스킬 재사용 상태를 초기화한다. 전투 중 관리 UI를 열어 능력을 바꾸는 기능은 없다.

### 주민과 복구의 표현
관리 화면 상단에 통일된 작은 전경을 둔다. 점령 중에는 적 깃발과 폐쇄된 시설, 해방 후에는 주민 귀환과 새 깃발, 정비 후에는 농촌의 논밭/수로와 창고 지붕/짐수레가 회복된 모습을 보여준다. 도형·색·짧은 상태 문구로 먼저 표현한다.
논밭 복구와 주민의 훈련 지원은 훈련장, 창고 수리와 물자 운송은 보급창의 효과 설명에 연결한다. 주인공만 일을 하고 주민은 무의미하게 서 있는 구성이 되지 않게 한다.
별도 쌀 화폐, 세금 타이머, 오프라인 수입, 자동 반란, 주민 AI 경로 탐색은 이번에 없다. 후속 경영 확장은 플레이 피드백 이후 결정한다.

## 4. 동료는 해금 후 실제 전투한다
챕터마다 1명, 최종5명. 1명 동행 또는 혼자 출정 중 선택한다. NPC는 장착만 하는 능력치 아이콘이 아니다.
챕터1의 초소 최초 승리에서 군자금, 해방 상태, 챕터 클리어, 궁수 해금을 같은 저장 변경으로 확정한다. 화면 흐름은 승리 결과 → 짧은 합류 장면 → 동료 선택 → 지도다.
합류 직후 '궁수와 농촌 재도전'을 제공해 첫 챕터만 있는 빌드에서도 보상을 바로 체험하게 한다. 자동 재도전은 하지 않는다. 다른 동료는 역할과 해금 챕터만 표시하고 선택 불가다.
동료 해금과 선택 상태는 별도다. 로드 시 잠긴/미구현 동료 ID가 선택돼 있으면 동행 없음으로 정리하고 기록한다.

### 궁수 아야의 초기 동작
- 체력60, 기본 사격 피해7(기본 공격력20의35%), 사격 간격1.5초, 준비0.25초.
- 주인공 뒤쪽 약100px를 기준으로 따라간다. 짧은 이동은 보간하되 순간 위치 이동으로 공격을 회피하지 않는다. 경기장 경계에 맞춰 위치를 보정한다.
- 목표는 살아 있는 적 중 사거리360px 안의 가까운 대상. 목표 바닥 깊이에 맞추되 적 바로 옆까지 파고들지 않는다. 공격할 수 없으면 따라가기/깊이 맞추기로 돌아간다.
- 공격 준비가 시작되면 방향·발사 깊이를 고정한다. 표적이 피하거나 사망해도 유도탄으로 바꾸지 않는다. 다음 행동 때 새 목표를 고른다.
- 실제 투사체: 수평 속도600px/s, 최대 이동거리360px 또는 수명0.6초, 발사 높이35px, 작은 판정 반높이4px/깊이 반폭4px 초기값. 높이·깊이 범위를 대상과 비교한다. 명중 시 단일 대상 피해 후 제거한다.
- 주인공과 같은 아군 팀. 아군끼리 피해 없음. 투사체는 아군을 관통하고 적/경기장 끝/최대 사거리에서 종료한다.
- 화살은 적을 밀거나 띄우지 않고 큰 경직도 주지 않는다. 주인공의 연타를 지원 사격이 깨뜨리지 않게 한다. 작은 적중 섬광만 주고 주인공의 히트스톱을 원거리에서 발생시키지 않는다.
- 궁수는 피격 시 짧은 경직/밀림을 받고 체력0이면 해당 출정에서 이탈한다. 첫 버전은 지상 이동만 지원한다. 다음 출정에서 회복한다. 동료 이탈만으로 패배하지 않는다.
- 피해·사거리·속도는 데이터로 조절한다. 원거리 공격 로직은 향후 적 궁수와 공유할 수 있으나 미구현 적 궁수를 이번에 추가할 필요는 없다.

### 기존 코드에 필요한 연결
M1의 Battle.all_actors는 player+enemies만 반환하고, MeleeEnemy는 주인공 target을 고정으로 전달받는다. 아군을 그리기만 추가하면 사격/피격 처리가 누락된다.
동료를 공통 전투 참여자 목록과 피격·투사체 판정에 포함하되, 승리 조건은 encounter에 등록된 적만 센다.
적은 대기/접근 때 살아 있는 주인공과 동료 중 가까운 대상을 선택할 수 있다. 예고가 시작되면 대상 위치/방향을 고정하고, 공격 중 순간적으로 다른 목표를 추적하지 않는다. 목표가 사망/제거되어도 참조 오류 없이 공격 종료 뒤 재선택한다.
주인공의 마지막 타격뿐 아니라 동료의 마지막 화살, 여러 적의 같은 틱 사망에서도 완료 이벤트가 한 번만 발생해야 한다.

## 5. 방 정리, 던전 승리, 결과
거점 출정1회에 run_id1개를 부여한다. run은 active → resolved → committed 순으로 한 번만 진행한다. 방 이동 때 begin_run을 다시 호출하지 않는다.
일반 방은 살아 있는 필수 적0 AND 예정 웨이브/출현0일 때 room_cleared로 전이하며 문을 연다. 그 순간 거점 보상이나 결과 화면을 만들지 않는다.
보스방에서 보스가 사망하고 주인공이 생존하면 dungeon_completed를 거쳐 기존 거점 승리 후보 상태를 만든다. 같은 틱의 투사체/화염 포함 모든 피해 후 주인공도 죽어 있으면 패배를 우선한다.
일반 방 정리 시 남은 적 투사체/불을 제거한다. 방 이동 때 체력/스킬·회피 대기시간/동료 생존을 보존하고 일시적인 공격/입력/장면 참조를 정리한다. 보스 승리 후 결과 창 뒤에서 추가 피해가 발생하지 않게 한다.
패배/포기는 이번 출정의 상자 임시 군자금까지 폐기하며 기존 영구 상태를 유지한다. 재도전은 새로운 run_id와 초기화된 방/상자 상태로 시작한다.
보물방 상자는 run당1회: 생존 아군20%회복(부활 없음), 보류 군자금30. 보스 승리 시 기본100/20에 더해130/50을 한 번 저장한다. 미개봉은100/20이다.
결과 재열기·확인 연타·늦은 사망/상자 신호는 같은 run의 보상·치유를 재발급하지 않는다. 보스 완료가 확정된 run에서 미개봉 상자를 뒤늦게 받을 수 없다.

## 6. 저장과 실패
로컬 저장1슬롯, schema_version1을 초기안으로 둔다. 이미 HWR-002 저장이 생겼다면 실제 형식을 확인하고 필요한 이전 처리를 하며 무단 초기화하지 않는다.
저장 필드: schema_version, currency, sites별 liberated/management/repaired, 시설 구매 플래그, cleared_chapters, unlocked_companions, selected_companion_id, last_committed_run_id.
마을 접근 가능 여부와 공격력/최대체력은 저장된 사실에서 계산한다. 중복되는 파생값을 따로 누적 저장하지 않는다. 활성 전투·투사체·중간 체력은 저장하지 않는다.
출정 중 방 방문/상자 상태는 런타임이며 중간 저장하지 않는다. 보스 승리 시 상자 보류 금액까지 후보에 넣는다. 승리와 구매 각각에 대해 후보 상태 생성 → 조건 검증 → 임시 파일 기록/완전성 확인 → 이전 정상 저장 보존 후 교체 → 메모리 상태 반영의 흐름으로 처리한다.
초소 승리 시 보상만 저장되고 동료 해금이 사라지는 식의 부분 성공을 만들지 않는다. 현재 run_id가 이미 적용되었으면 재시도는 동일 결과를 반환한다.
저장 실패 시 기존 상태를 보존하고 '저장 재시도'를 제공한다. 결과 화면은 미저장임을 표시하고 새 보상/구매가 확정된 것처럼 다음 전투를 시작시키지 않는다. 재시도는 같은 후보 상태에 대해 수행하며 돈을 다시 더하지 않는다.
계속 실패하면 이전 저장으로 돌아가는 선택을 제공하고 이번 결과가 반영되지 않음을 알린다. 구매 실패는 비용도 효과도 적용하지 않는다.
손상 저장은 유효한 백업을 시도하고 복구하지 못하면 사용자에게 새 게임/취소를 제공한다. 새로운 schema_version을 임의로 낮춰 읽거나 원본을 바로 덮어쓰지 않는다.
자동 테스트와 수련장은 별도 저장 경로/무저장 모드로 실행해 사용자 캠페인을 변경하지 않는다.

## 7. 유지할 캠페인 인수 시나리오
아래 '승리'는 이제 각 거점의 보스 처치를 뜻한다. 방 상태/미니맵/신규 적/상자 확장 검증은 DUNGEON_COMBAT의 인수 항목을 추가한다.
1. 새 게임 → 농촌 승리 → 군자금100, 관리도40, 창고 잠김 → 정비 후60/60, 창고 개방.
2. 훈련장 구매 후 군자금0, 공격력20 기준21. 재입장/로드/거점 재도전 후에도21.
