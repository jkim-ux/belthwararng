# HWR-GRASS-001 R3 — 실제 마을에 맞춘 고정 잔디와 흙길

작성: 2026-09-14 UTC

작업 진입점: [TO_CLAUDE_GRASS.md](../TO_CLAUDE_GRASS.md)

## 1. 목표와 확인한 원인

사용자는 전체 마을 콘셉트의 분위기를 선호하지만 실제 게임에서 재현 가능한 구성을 요구했다. 촘촘한 풀 타일을 넓게 반복한 결과와 어색한 바람은 거절했다. 목표는 **차분하게 이어지는 낮은 지면, 잘 읽히는 흙길, 가장자리에 모인 개별 잎, 정령과 건물의 선명한 실루엣**이다.

검토한 구현은 풀 브랜치 `80000e2df6b19f677169cfb258e13315d770006e`다. 착수 시 이후 변경을 확인하고 보존한다.

| 코드·보고에서 확인한 사실 | 설계상 판단 |
|---|---|
| 타일마다 128×64 높이장 16,384면 + 흙 벽 + 앞뒤 카드 2장, 총 17,156면 | 넓은 잔디가 개별 풀잎보다 연속된 둔덕으로 표현된다. 전체 지면의 높이장을 교체한다. |
| 70백분위 높이 보존, 표면 normal 강도 1, 타일별 색 변화 | 굴곡·잔무늬·색 변화가 함께 넓게 반복된다. 색 보정만으로 해결된다고 가정하지 않는다. |
| 보고서 기준 실제 카메라에서 한 칸 약 170×26px | 모든 잎을 촘촘하게 모델링해도 읽히기 어렵다. 입체 잎은 윤곽이 드러날 위치에 집중한다. |
| 풍속에 따른 정점 이동과 wind_sheen 밝기 변화 | 둘 다 제거한다. 풀의 시간 의존 변형과 밝기 진동을 개선하는 추가 작업은 하지 않는다. |
| M4에서 192타일 검토 장면 약 5.3ms, 실제 전체 마을 프레임 미측정 | 현재 보고는 풀 단독 부하의 근거다. 문제를 성능 부족으로 단정하거나 전체 게임 190FPS로 인용하지 않는다. |

단일 에셋의 감면과 원본 디테일 보존에 치우쳤던 이전 기준을 수정한다. 기존 원본·베이크 도구·완료 보고는 남긴다. 지역별 MultiMesh, 공유 리소스, 건물 점유에 따른 숨김 처리처럼 쓸 수 있는 연결 코드는 재사용한다.

## 2. 현재 게임과 콘셉트의 차이

실제 카메라는 직교, 수평에서 아래로 20°, ORTHO_SIZE 8.5다. 좌표는 X=논리 가로×2.0, Z=논리 깊이×0.9, 지면 Y=0이다. 이 계약과 작은 마을 크기를 유지한다.

현재 농촌 템플릿은 16×12이며 아래쪽에 가로 흙길, 입구로 내려오는 세로 길, 오른쪽 경계의 강이 있다. 콘셉트샷의 굽은 길·강 위치·꽃밭을 그대로 옮기면 실제 지형과 배치 규칙이 바뀐다. **이번에는 실제 템플릿을 기준으로 구성하고 그림의 색·밀도·여백을 적용한다.**

콘셉트의 풍성한 꽃 장식, 바구니, 모든 건물의 세부 형태가 현재 에셋으로 준비됐다고 가정하지 않는다. 우물·나무·울타리·창고·온실 등은 환경 담당의 실제 게임용 산출물을 사용한다. 미완료 모델을 원시 도형으로 대체한 상태는 배치 초안으로 표시하고 최종 미술 검수와 구분한다.

## 3. 구현 구조

### A. 넓은 바닥: 기존 불투명 지형 메시 + 공유 재질

`VillageStage3D._build_terrain()`의 바닥 메시를 활용한다. 풀 타일마다 17k 높이장을 덮는 런타임 방식은 중단한다. 기존 평면은 칸당 2삼각형, 192칸 전체 384삼각형 규모다. 강의 낮은 높이와 필요한 경계 면은 별도 유지하며 모든 지형이 무조건 평평해진다는 뜻이 아니다.

- 잔디는 세이지·연한 올리브의 낮은 대비, 흙은 따뜻한 베이지·갈색을 쓴다. 넓은 색 변화와 작고 부드러운 표면 질감을 나누어 설계한다.
- 지면의 연속된 월드 XZ 좌표로 텍스처를 샘플링한다. 칸마다 UV를 0~1로 다시 시작하거나 랜덤 색을 주지 않는다. 기존 체크무늬 명암도 일반 감상 모드에서는 제거한다.
- 높이 displacement는 사용하지 않는다. normal은 우선 없이 비교하고 필요할 때 아주 약하게 추가한다. 원본의 고대비 베이크 normal을 강도 1로 그대로 연결하지 않는다.
- 단색 초록 판이나 대비 높은 절차적 노이즈를 최종 잔디로 제출하지 않는다. 밑색·작은 잎의 흔적·미묘한 흙 입자가 함께 보이되 정령보다 눈에 먼저 들어오지 않는 실제 텍스처가 필요하다.
- 지면은 계속 불투명하고 연속되어야 한다. 건물 밑의 풀 묶음을 숨겨도 지면이 빠지거나 구멍이 나지 않는다.
- 넓은 바닥 텍스처에 진한 방향성 그림자를 굽지 않는다. 주요 물체의 접지 그림자는 실제 조명에서 받는다.

### B. 흙길: 같은 지면 재질 안에서 혼합

현재 프로젝트는 GL Compatibility다. Godot Decal 노드는 이 렌더러에서 지원되지 않으므로 필수 기능으로 쓰지 않는다. 같은 바닥 shader의 잔디·흙 혼합을 사용한다.

1. 템플릿의 `p`·`e`와 실제 완공된 road의 셀을 기준으로 길 마스크를 만든다. 숲·암반·강·공사장·밭의 기존 구분은 별도로 보존한다. 현재 풀 목록에 있는 `e`는 입구이므로 풀 묶음 배치에서 제외한다.
2. 시각용 마스크는 논리 셀보다 높은 해상도로 만든다. 예: 칸당 32px면 512×384px. 텍스처 갱신은 설치·철거 등 상태 변화 때만 하고 매 프레임 만들지 않는다.
3. 길의 중심은 흙으로 유지한다. 가장자리 약 0.1~0.2 월드 단위만 불규칙하고 부드럽게 섞는 초기안을 비교한다. 논리 셀을 통째로 블러해 강·절벽까지 잔디가 번지게 하지 않는다.
4. 길찾기·클릭 판정·건물 허용 조건은 바꾸지 않는다. 표시용 가장자리 때문에 새로운 길이 열린 것처럼 보이지 않게 한다.
5. 평행한 큰 투명 판을 여러 장 겹쳐 길을 만들지 않는다. 바닥과 길의 z-fighting을 구조적으로 피한다.

Ground mask는 데이터 텍스처, albedo는 색 텍스처다. 마스크의 sRGB 변환, 정점 색의 이중 선형 변환을 피한다. 기존 `f`·`Q`·`#`·`d`·`x` 표시를 잔디로 덮어 기능 구역이 사라지지 않게 한다. `W`의 바닥도 잔디와 자연스럽게 이어지도록 강한 칸별 색 차이를 완화한다.

### C. 입체 풀: 작은 묶음 3종부터

새로 필요한 3D 아트는 **짧은 풀잎 묶음, 둥근 작은 잎/클로버 묶음, 조금 높은 가장자리 풀 묶음** 3종부터 시작한다. 각 묶음은 몇 개의 구별되는 잎으로 만든다. 잎이 합쳐진 뾰족한 둔덕이나 촘촘한 바닥 덩어리로 만들지 않는다.

- 사용자 Tripo의 잎 모양·색을 재료로 삼는다. 개별 잎 추출이 깨끗하게 안 되면 간단한 휘어진 잎 메시와 새 공유 텍스처로 재구성한다. 전체 193만면을 다시 큰 높이장으로 굽는 작업을 반복하지 않는다.
- 초기 제작 예산은 묶음당 대략 100~400삼각형, 가까운 한 화면에 60~120묶음 정도부터 시작한다. 최소 면수나 반드시 채울 개수가 아니다. 실제 화면 밀도와 성능을 보고 줄이거나 조정한다.
- 불투명 잎 메시를 우선 비교한다. 카드가 필요한 일부 잎은 alpha scissor를 사용하고 검은 테두리·mipmap·양면 법선을 확인한다. 투명 블렌드 카드 수백 겹은 피한다.
- 뿌리는 Y=0 부근, 높이는 정령 발과 몸의 상대 크기를 보고 정한다. 주요 이동 공간에서는 정령의 발과 작은 몸이 풀에 파묻히지 않게 한다.
- 길 가장자리·나무 밑·울타리 아래에 소규모 군집과 빈 구간을 번갈아 둔다. 모든 셀 중심이나 길 전체에 균일한 띠로 놓지 않는다.
- 지역별 MultiMesh와 공유 재질을 재사용한다. 월드 위치/셀과 고정 seed로 배치를 계산해 로드·카메라 이동·건물 갱신 때 재추첨되지 않게 한다.
- 건물 footprint와 회전에 맞는 문 앞, 길·입구·물·작업 칸은 비운다. 공사 중에도 숨기고 철거 시 같은 배치가 복원되게 한다. 외곽의 작은 장식 여백만 처리하고 건설 가능 면적을 줄이지 않는다.
- shader의 시간에 따른 이동·gust·sheen은 없다. 게임 시간과 정령의 바람 농사 동작은 계속 정상 동작해야 한다.

### D. 물체와 배경

나무와 큰 건물은 뒤쪽/경계에서, 작은 밭·우물·정령은 앞쪽에서 읽히도록 실제 검토 장면을 구성한다. 사용자가 놓은 건물을 자동 재배치하지 않는다. 환경 원본 경량화는 HWR-ENV-001 담당이고 본 작업에서 모델 9종을 새로 제작하지 않는다.

기존 배경색과 backdrop을 우선 사용한다. 원경이 부족할 경우 후속으로 경계 밖 고정 배경판/먼 나무를 추가할 수 있으나, 플레이 영역의 길·우물·나무는 실제 공간과 가림이 맞아야 한다. 배경 그림으로 없는 건물을 있는 것처럼 보이게 하여 구현 증거로 제출하지 않는다. 콘셉트의 꽃 장식과 새로운 건물 제작은 이번 지면 교체의 필수 범위가 아니다.

지면의 색 문제를 해결하려고 전체 화면의 채도·노출을 크게 바꾸지 않는다. 흰 정령의 털과 기존 우물·나무 재질을 함께 확인한다.

## 4. 필요한 산출물과 파일 연결

| 산출물 | 시작 규모 / 연결 |
|---|---|
| 낮은 대비의 반복 가능한 잔디 BaseColor, 흙 BaseColor | 각각 1K부터. 반복 경계와 실제 카메라에서 표면 질감 검수. 필요 시 2K 이유 기록 |
| 풀 묶음 3종 + 공유 재질/텍스처 | 원본 출처와 제작 절차, 피벗·치수·면수 기록. 새 UV면 재베이크 또는 그 UV에 맞는 텍스처 제작 |
| 정적 지면 shader와 마스크 생성 | `game/assets/environment/grass/` 내부. `_build_terrain()`에 연결 |
| 정적 풀 배치 | 기존 `grass_field.gd` 구조 활용. `sync_buildings()`의 footprint 숨김을 새 묶음에 연결 |
| 검토 장면과 보고 | 실제 stage·에셋 factory 사용, 같은 카메라의 전후 캡처, 업데이트된 manifest |

목표 분위기에는 **새 텍스처와 작은 잎 모델 제작이 실제로 필요하다.** 기존 재질의 tint 조절만 한 결과를 재구성 완료로 처리하지 않는다. 텍스처 생성/편집 도구가 없으면 사용할 수 있는 원본에서 재베이크·정리하고, 필요한 아트가 아직 미완성이면 그 상태를 명시한다.

런타임의 active asset 목록을 manifest로 명시한다. 옛 grass_tile_a/b, 바람 shader, 옛 테스트 장면은 참고용으로 보존할 수 있으나 새 기본 마을이 실수로 옛 자원을 참조하지 않게 한다. 원본 GLB를 삭제·덮어쓰지 않는다. 게임용 개별 파일은 기존 전달 규칙대로 25,000,000 bytes 이하를 유지한다.

## 5. 검수는 실제 한 화면부터

1. **전후 기준:** 같은 브랜치 기반으로 기존 결과와 새 결과를 1280×720, 직교 20°, 크기 8.5, 같은 조명에서 캡처한다. 카메라와 노출을 바꿔 바닥 문제를 감추지 않는다.
2. **대표 구역:** 실제 stage를 사용하는 테스트 상태에 흙길과 잔디의 경계, 나무 1개, 우물 1개, 울타리 2~3개, 밭 1개, 정령을 담는다. 카메라에 들어오는 구역만 먼저 다듬는다. 실제 논리 규칙으로 배치하고 사용자 저장을 덮어쓰지 않는다. 환경 모델이 아직 미완성이면 지면 검증과 합본 미술 검증을 분리한다.
3. **정상 크기 평가:** 확대된 풀 하나보다 축소하지 않은 게임 화면에서 여백·색·잎 윤곽·정령의 발·흙길 방향이 잘 읽히는지 본다. 단색 판, 반복된 네모, 반짝이는 점, 부풀어 오른 융단처럼 보이면 재질/배치를 수정한다.
4. **짧은 실제 플레이:** 마을 바로 진입 → 이동·카메라 추적 → 미리보기 → 설치/공사 → 철거 → 다시 방문을 확인한다. 풀 숨김/복원, 길의 마스크, 문 앞, 클릭 셀이 맞아야 한다. 정지 풀의 밝기·위치가 시간에 따라 출렁이지 않는지 확인하는 짧은 이동 영상은 유용하나 바람 ON 영상은 필요 없다.
5. **전체 확장:** 대표 화면이 위 기준을 만족하면 같은 규칙을 전체 마을에 적용한다. 추가 지형 종류, 화면 가장자리, 건물이 많은 구역에서 이음새·가림·군집 밀도를 확인한다.
6. **성능:** 실제 Godot/GPU/renderer와 해상도를 기록한다. 새 단독 검사와 정령·건물·UI가 포함된 실제 마을을 구분한다. 같은 장면/카메라/그림자 조건에서 평균과 p95 프레임 시간을 비교한다. 16/192칸 지형 검사는 유지할 수 있지만 **192개 고밀도 풀 타일 배치**는 새 완료 기준이 아니다.

전후 이미지는 후처리 없는 실제 엔진 캡처로 제출한다. 이번에 기준으로 삼은 콘셉트는 미술 방향이며 실행 증거가 아니다. 실물 아트·합본·GPU 검수 중 못 한 항목을 명시한다. 옛 보고를 수정해 과거 결과가 R3였던 것처럼 만들지 말고 `reports/HWR-GRASS-001_R3.md`에 변경과 실제 확인 범위를 남긴다.

## 6. 기존 테스트에서 바꿀 부분

기존 테스트의 타일당 LOD0 10k 이상, 150/192개의 고정 타일 인스턴스, 타일 벽 깊이, UV2 바람 마스크, wind uniform 의무 조건은 옛 표현 방식에 대한 검사다. 새 방식에 강제하거나 수치를 맞추려고 불필요한 메시를 추가하지 않는다.

가져오기·재질 연결·원본 보존·리소스 공유 검증을 유지하고, 실제 위험에 해당하는 마스크 좌표·강/길 제외·회전한 건물의 footprint/문 앞 제외·철거 후 결정적 복원·정상 설치 입력을 기존 검사에 반영한다. 스크린샷 없는 숫자 통과는 미술 완료가 아니다.

## 7. 병행 작업과 통합

풀 담당은 기존 풀 작업을 이어 가고 최신 main의 이 지시를 반영한다. main에 아직 없는 풀 구현을 잃지 않도록 브랜치/미커밋 상태를 먼저 확인한다. 환경 담당과 별도 worktree를 유지한다.

`village_stage_3d.gd`는 공유 파일이다. 본 담당은 지면 재질·풀 배치·점유 연동 변경을, 환경 담당은 모델 factory·재질·피벗/축척 연결 변경을 각각 기록한다. 파일 통째 덮어쓰기나 한쪽 ours/theirs 선택으로 해결하지 않는다. 통합 후 같은 stage에서 새 바닥과 새 환경 모델이 모두 보이는지 검증한다.
